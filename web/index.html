    Hack your browsing

    With Browser Lambdas, your browsing experience is hackable in the best way possible: write lambda functions and execute them on the web to give yourself new tools, capabilities, and shortcuts.

    It started as just functions but now also includes a mod’able shell, persistant key-value storage, secrets and URL based trigger automations.

    Use it to work faster, reduce mental load, avoid clicks or just have fun. Track your stuff in git and sync with the extension via the CLI tool baah.

    How It Works

    The intended flow is simple:

    1. Write a lambda function on your machine and track it with git.
    2. Sync it to the extension via baah push.
    3. Go to a page.
    4. Execute the function.

    The extension keeps a copy of your function and injects it together with a small runtime into a JavaScript context associated with the target page. The runtime exposes APIs for key-value storage, secrets, and more through the async ctx object. These APIs establish secure channels between the extension background worker and the runtime.

    Your function runs instantly and disappears when it’s done. It can manipulate the page DOM, open tabs, act on inputs, and more. Basically you are Neo now.

    Overview

    The functions you write are just plain JavaScript functions. To spice things up you can use the ctx API to:

    1. Use key-value storage (KV) to read/write persisted values between function calls
    2. Read-only access secrets at runtime to make API requests
    3. Parse rich arguments to your functions (positional, flags etc)
    4. Run other lambda functions
    5. Manipulate tabs

    The surface of the ctx object looks like this:

    FeatureAPI ExamplesPurpose
    Argumentsctx.args.all()Read command‑line flags passed to a lambda
    Storagectx.kv.get(), ctx.kv.set()Persist values between lambdas
    Secretsctx.secrets.get()Access configured secrets
    Runctx.run("foo bar"), ctx.tabs.this().run()Execute another lambda on the current page
    Tabsctx.tabs.new(), ctx.tabs.all()Open, list and control browser tabs

    Args

    ctx.args.all()

    Returns an object with all command‑line arguments.

    Positional arguments

    my-lambda cats dogs
    const { 0: first, 1: second } = ctx.args.all();
console.log(first, second);

    Long flags

    my-lambda --title "Hello" --count=5 --dry-run
    const { title, count, dryRun } = ctx.args.all();
console.log(title, count, dryRun);

    Short flags and aliases

    my-lambda -u alice -p hunter2
    const { username, password } = ctx.args.all({ u: 'username', p: 'password' });
console.log(username); // "alice"
console.log(password); // "hunter2"

    kv

    Key-value map stored persistently in browser extension storage. Values are stored as JSON, so you can save plain strings or complex objects without stringifying.

    ctx.kv.get(key)

    Fetches a value when the item allows the current page and execution world. 

    const value = await ctx.kv.get("my-key");
console.log(value);

    Missing or denied keys return null with a shell warning. A stored null also returns null, without a warning.

    ctx.kv.set(key, value)

    Stores a JSON-compatible value and returns true when allowed, or false with a warning when blocked.

    await ctx.kv.set("my-key", "hello");

    You can store objects too:

    const snippet = { url: location.href, text: window.getSelection().toString() };
await ctx.kv.set("last-snippet", snippet);

// later on another page
const saved = await ctx.kv.get("last-snippet");
console.log(saved.text);

    Secrets

    ctx.secrets.get(key)

    Read-only access to a secret added via the extension workspace. 

    const token = await ctx.secrets.get("API_KEY");
const res = await fetch("https://api.example.com", {
  headers: { Authorization: `Bearer ${token}` }
});
console.log(await res.json());

    Run

    ctx.run(cmd)

    Runs another lambda on the current page. Provide the full command exactly as you would type it in the shell.

    await ctx.run("other-lambda arg1 arg2");

    Chain

    Return a value from one lambda and pass it to the next through command arguments.

    $ tree functions
functions
├── count-links.js
├── show-count.js
└── chain.js

$ cat functions/count-links.js
return document.querySelectorAll('a').length;

$ cat functions/show-count.js
const { count } = ctx.args.all();
console.log(count);

$ cat functions/chain.js
const count = await ctx.run("count-links");
if (count !== undefined) {
  await ctx.run(`show-count --count ${count}`);
}

    This also works with the tab .run() command.

    Return JSON-compatible values. Anything else yields undefined.

    Tabs

    ctx.tabs.new(url?)

    Opens a new tab with the specified URL.

    await ctx.tabs.new("https://example.com");

    ctx.tabs.new().run(lambda, args?)

    Opens a new tab and runs a lambda inside it.

    await ctx.tabs.new("https://example.com").run("scrapetool --include-metatags");

    ctx.tabs.new().focus()

    Brings a newly opened tab into focus.

    const tab = await ctx.tabs.new("https://example.com");
await tab.focus();

    ctx.tabs.new().close()

    Closes a newly opened tab after you're done with it.

    const tab = await ctx.tabs.new();
await tab.close();

    ctx.tabs.this().run(cmd)

    Runs a lambda on the current tab. This is synonymous with ctx.run().

    await ctx.tabs.this().run("other-lambda arg1");

    ctx.tabs.all()

    Returns wrappers for all open tabs.

    const tabs = await ctx.tabs.all();
for (const tab of tabs) {
  console.log(tab.title);
}

    Security

    Approach

    Browser Lambdas was build to give developers great powers. And as we all know with greater powers - comes great security checks. Because it’s just not a bad idea to manage risks and exposure. You could screw yourself over by accident or bad actors could try and take advantage of you. The extension and cli tool both take the same approach: safe by default and loosy goosy if you so choosy. Almost. This article covers the layers of protection in both pieces of software and what you can turn on/off.

    Terminal

    The main risk managed here is a malicious website:

    1. opening the terminal
    2. typing commands into it.
    3. reading data from it
    4. DOS’ing it

    The overall approach to mitigate this is isolating the terminal from the page it works on:

    1. The content script injects the terminal into pages when:

      • the user opens it via the extension popup/menu,
      • the user presses the keyboard shortcut, or
      • Always on is enabled in Settings (off by default).

      The shortcut checks event.isTrusted, a browser-set flag that website-created keyboard events cannot set. This prevents websites from opening the terminal with synthetic keystrokes.

    2. The injected terminal is embedded in an iframe. This is essentially an isolation layer prevents B and C.

      Plus it reduces the surface for DOS attacks but it does not mitigate it fully

    Function injection

    When a user runs a lambdas on a website a few things happens:

    1. Terminal communicates to popup script that user wants to run a lambda function on this site
    2. Background worker builds a function (essentially a small runtime + the lambda function)
    3. Injects it via browser APIs into either the user world or main world of the page
    4. Results and data is send back into the terminal

    This opens a few risks on malicious websites:

    1. They try to trigger existing functions
    2. They could try to intercept messages
    3. They could try and manipulate valid functions
    4. They could try to pretend to be valid runtimes

    baah

    Functions, triggers and styles should all be tracked in git on your machine. To sync them and run with the extension you need to use the CLI tool baah.

    In short it:

    1. A baah.toml file is used to decide what files get synced.
    2. baah push starts a server waiting for connected browsers.
    3. When the extension workspace is open it polls the changes.
    4. You approve the diff.
    5. Ready to go.

    Connections

    The baah CLI tool revolves around two resources: connections, which are individual authenticated connections to browsers on your machine, and baah.toml files with instructions for syncing a project through those established connections.
